## 文書と実際の処理の関係

02〜05は、中心となる検索処理から利用者の画面へ、内側から外側へ理解する順番です。

実際のリクエストはバックエンドが全体を取りまとめ、次のように往復します。

```text
05 フロントエンドで質問する
  ↓
04 バックエンドで認証・入力検証をする
  ↓
02 データ検索とルールでページ・節を選ぶ
  ↓
03 プロンプトを組み立ててモデルに回答させる
  ↓
04 バックエンドで出典・履歴・利用回数を処理する
  ↓
05 フロントエンドに回答を表示する
```

06はこの処理の品質を検証する方法、07は資料とコードを本番へ反映する手順です。
01は構成全体の判断理由、08は判断の根拠となる実測、09は運用を続けるうえで残る課題です。

## 最初に知っておく言葉

- **フロントエンド**: 利用者がブラウザで見る画面です。`web/`にあります
- **バックエンド**: ログイン、資料検索、AIへの質問、保存を行うサーバーです。`backend/`にあります
- **索引（インデックス）**: Wikiや公開資料を、質問から探しやすい形へ整理したファイルです
- **チャンク**: 長い資料を見出し単位で分けた検索の単位です
- **Firestore**: 履歴、利用回数、共有アシスタント、フィードバックなどの保存先です
- **デプロイ**: 手元の変更を、部員が実際に使う本番環境へ反映する作業です

## 普段の運用

WASA Chatは、Wiki、公式サイト、フライトシミュレータガイドの内容を
あらかじめ取得して索引にしています。**公開元が更新されても、WASA Chatへは自動反映されません。**

1. 管理画面の「資料更新」で公開元の変更を確認します
2. 変更があれば、手元で`python ingest/rebuild.py`を実行します
3. 取得内容、索引、検索検査の結果を人が確認します
4. [07-デプロイと更新](07-デプロイと更新.md)の手順で索引を本番へ反映します

管理画面の更新確認も`ingest/rebuild.py`も、自動では本番公開しません。
非公開Wikiの取得内容や誤編集を、人が確認してから公開するためです。
手元で差分だけ確認したい場合は`python ingest/check_updates.py`を使います。

利用者のフィードバックはFirestoreへ保存されます。画面やメールでは確認せず、
[06-評価とフィードバック](06-評価とフィードバック.md)の手順でJSONLまたはCSVへ書き出します。
質問と回答には非公開Wikiの内容が含まれうるため、書き出したファイルはコミットしません。

## どの文書を正本にするか

同じ説明を複数の文書へ増やすと、片方だけ更新されて食い違います。
変更内容ごとの正本は次のとおりです。

| 変更する内容 | 正本 | 例 |
|---|---|---|
| 設計判断の理由 | [01-設計方針](01-設計方針.md) | RAG方式、認証方式、段階的導入 |
| 索引・検索・決定的ルール | [02-データ検索とルール](02-データ検索とルール.md) | チャンク、マスキング、参照範囲、入力上限 |
| モデルへ渡す指示 | [03-プロンプト](03-プロンプト.md) | system規則、ページ選択、回答生成、入力順 |
| 認証・API・保存 | [04-バックエンド](04-バックエンド.md) | Wikiログイン、Cookie、Firestore、利用回数 |
| 現在の画面挙動 | [05-フロントエンド](05-フロントエンド.md) | 履歴、アシスタント、通知、管理画面 |
| 評価と改善の手順 | [06-評価とフィードバック](06-評価とフィードバック.md) | 自動評価、人手評価、書き出し、失敗分類 |
| 本番作業 | [07-デプロイと更新](07-デプロイと更新.md) | 初回構築、更新、ロールバック |
| 数字と誤答の履歴 | [08-測定記録](08-測定記録.md) | Recall、チャンク数、モデル比較、再現コマンド |
| 将来の運用課題 | [09-運用課題](09-運用課題.md) | 所有権、監視、混雑、承認の更新 |

プロンプトと決定的ルールについて、**実際の動作の最終的な正本はコード**です。
文書は規則の目的を説明するものなので、食い違いを見つけたらコードと文書を一緒に直します。

- プロンプト: `backend/internal/assistant/assistant.go`、`backend/internal/pipeline/pipeline.go`
- 決定的ルール: 対応するGoまたはPythonコード

## 最低限の検証

変更後は、少なくとも次を実行します。

```bash
cd backend
GOCACHE=/private/tmp/wasa-go-cache go test ./...

cd ../web
npm test
npm run build

cd ..
python -m py_compile rag/pipeline.py eval/response_mode_eval.py
```

- 通常の単体テストは実Wikiへ接続しません
- 実Wikiで確かめるときだけ、秘密値を`.env`へ置いて`LIVE_WIKI_TEST=1`を付けます
- `.env`、`dump/`、`data/`、`eval/golden.json`は非公開情報を含むためコミットしません
